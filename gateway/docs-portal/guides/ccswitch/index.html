工具接入

CCSwitch

更新 CCSwitch → 编辑现有供应商 → 刷新模型列表 → 设置最新 Terra → 完全退出并重开。

推荐路径 · 更新后编辑现有供应商刷新模型列表 → 保留 5.6 及以上 → Terra 用最新版本

教程使用自绘示意，不展示真实账户、Key、余额或本机路径。已有皮皮虾 AI 供应商直接编辑即可；没有供应商时再从 API 密钥页面导入。

打开 API 密钥页面 ↗下载最新 CCSwitch ↗

1. 更新 CCSwitch

前往 CCSwitch 官方 Releases 页面，安装最新版本。更新后重新打开 CCSwitch；如果它仍显示旧界面，完全退出后再启动一次。

2. 打开 Codex 供应商编辑页

  1. 在顶部切换到 Codex。
  2. 找到正在使用的皮皮虾 AI 供应商，点击卡片右侧的铅笔形编辑按钮。
  3. 确认 API 请求地址是 https://api.psydo.top/v1，协议选择 Responses。不要把 API Key 写进教程、截图、工单或 Git。
没有现成供应商？

先在API 密钥页面 ↗创建或选择对应编程分组的 Key，再使用「导入到 CCS」。导入链接包含 Key，只在本机浏览器和 CCSwitch 之间使用。

3. 获取模型列表并清理旧模型

在编辑页的“模型列表”区域点击获取模型列表，等待当前 Key 的列表刷新。只勾选 5.6 及以上模型；按当前版本可保留 gpt-5.6-sol、gpt-5.6-terra、gpt-6-astra、gpt-6.1-sol 和 gpt-6.1-terra。取消不需要的旧模型，并删除列表中残留的 gpt-5.5。

点击“应用”或“保存模型列表”，确认 5.5 没有继续出现在已选列表里。

4. 设置默认模型、子代理和自动审批

  1. 默认模型选择 gpt-5.6-sol。
  2. “子代理模型”选择当前列表中的最新 Terra，本次应为 gpt-6.1-terra。
  3. “自动审批模型”“自动审批使用模型”或同义字段也选择 gpt-6.1-terra。如果当前版本只有一个自动审批下拉框，就选择同一个最新 Terra。
  4. 保存供应商并启用它。保存前检查这些字段没有回退到 gpt-5.5。

5. config.toml 的推荐值

如果你通过 CCSwitch 的 Config 视图或本地 ~/.codex/config.toml 管理 Codex，可以把主模型和供应商配置整理成下面的结构。真实 Key 由本机认证流程提供，不要粘贴到文档或共享配置。

config.toml
model_provider = "custom"
model = "gpt-5.6-sol"
model_reasoning_effort = "high"
disable_response_storage = true
service_tier = "priority"

[model_providers.custom]
name = "皮皮虾 AI"
base_url = "https://api.psydo.top"
wire_api = "responses"
requires_openai_auth = true

若 CCSwitch 会自动写入供应商段落，以 CCSwitch 的保存结果为准，不要同时手改多个入口。模型名必须来自刚刷新过的当前 Key 列表。

6. 完全退出 Codex，再重新打开

必须完成：保存并启用 → 完全退出 → 重新打开

在 CCSwitch 修改配置后，先保存手头任务，再完全退出 Codex、Claude Code 等目标工具。桌面端退出应用及托盘/菜单栏中的后台实例；CLI 结束正在运行的会话；VS Code 扩展需关闭承载它的 VS Code 后重新打开。只关对话、新建任务或只重启 CCSwitch，都不等于重启目标工具。

7. 发送简单任务并核对记录

重开后发送一条短请求，确认实际使用的是刚设置的模型。然后打开调用记录 ↗，核对模型、请求状态和消费来源。仍然 Reconnecting 时按连接问题指南排查。

第三方工具：确认 UA 被保留

使用客户端或中间代理对接时，确认实际发出的请求带有 User-Agent。工具已正常发送自身 UA 时保留它；支持自定义 Headers 的工具可补充真实应用标识。不要假定 CCSwitch 本身的配置会替所有工具发出 UA，也不要用 UA 冒充其他工具。

Claude Code

  1. 在 CCSwitch 顶部选择 Claude，点击右上角“+”，选择自定义配置，供应商名称可填“皮皮虾 AI”。
  2. Endpoint 填写 https://api.psydo.top，不要添加 /v1。
  3. 认证令牌填写您自己的皮皮虾 AI API Key；保存后获取模型列表，模型以控制台可见范围为准。
  4. 启用该供应商后，完全退出再重新打开 Claude Code。

Codex

  1. 在 CCSwitch 顶部选择 Codex，找到皮皮虾 AI 供应商，点击铅笔形的编辑入口。
  2. 确认 Base URL / Endpoint 为 https://api.psydo.top/v1，接口协议选择 Responses。真实 API Key 只保存在本机配置中。
  3. 进入模型列表，点击获取模型列表刷新当前 Key 的可用模型，不要继续使用旧缓存。
  4. 勾选 gpt-5.6-sol、gpt-5.6-terra、gpt-6-astra、gpt-6.1-sol、gpt-6.1-terra 等 5.6 及以上模型；取消旧模型的勾选，并删除列表中残留的 gpt-5.5。
  5. 保存并应用模型列表。若列表中出现更新的 Terra 版本，优先使用当前 Key 刷新后返回的最新模型名。

设置默认模型与 Terra

默认模型建议使用 gpt-5.6-sol。在“子代理模型”以及“自动审批模型/自动审批使用模型”等字段中，统一选择当前列表里的最新 Terra；按本次模型列表应为 gpt-6.1-terra。如果 CCSwitch 只显示一个自动审批相关下拉框，也选择同一个最新 Terra。

保存前再检查一次：没有选中 gpt-5.5，默认模型和 Terra 模型都来自刚刚刷新过的列表。

让 Codex 在项目内调用生图

这是推荐方式：CCSwitch 继续使用普通编程分组 Key驱动 Codex；生图分组 Key 只保存在目标项目的本地配置文件里。需要生图时，直接在项目中对 Codex 说“调用皮皮虾生图 Skill 生成一张……”。

  1. 在控制台“API 密钥”额外创建一把 Key，分组选择生图 API 分组。不要改动 CCSwitch 正在使用的编程 Key。
  2. 在需要生图的项目根目录创建 .pipixia-image/config.json，写入下方配置；它只存在于本机项目中。
  3. 把 .pipixia-image/config.json 加入该项目的 .gitignore，随后让 Codex 创建并使用生图 Skill。
  4. 以后只需告诉 Codex 图片需求和保存位置；它通过 Skill 读取本地配置并调用图片生成接口。
.pipixia-image/config.json
{
  "base_url": "https://api.psydo.top/v1",
  "api_key": "在这里粘贴生图 API 分组 Key",
  "model": "在控制台模型列表确认的图片模型名称"
}
.gitignore
.pipixia-image/config.json

把下面整段发给项目里的 Codex：

给 Codex 的 Skill 创建提示词
请在当前项目创建一个本地生图 Skill，供后续按自然语言调用皮皮虾 AI 图片生成。

要求：
1. 创建 .codex/skills/pipixia-image/SKILL.md，说明何时调用、参数、失败处理与输出目录。
2. 只从项目根目录的 .pipixia-image/config.json 读取 base_url、api_key、model；若文件或字段缺失，明确提示用户补充，绝不猜测或写入真实 Key。
3. 使用 POST {base_url}/images/generations，Authorization 为 Bearer {api_key}，请求头必须包含 User-Agent: pipixia-client/1.0，请求 JSON 包含 model、prompt、size。
4. 同时兼容响应里的 data[].url 与 data[].b64_json；将图片保存到 output/images/，文件名使用安全的时间戳与序号。
5. 创建一个可重复调用的本地脚本，不要把 Key 写进代码、日志、命令历史、Git 或输出文件。
6. 在 .gitignore 中确保 .pipixia-image/config.json 被忽略；不要修改或覆盖现有 .gitignore 规则。
7. 调用成功后只汇报生成文件路径、模型和必要的错误信息；不得回显 API Key。
8. 先检查现有项目技术栈，沿用已有语言和脚本约定；完成后给出一次不含真实 Key 的验证说明。

生图 Key 说明：生图 Key 与 CCSwitch 的编程 Key 都属于同一账户，可使用账户余额或各自绑定的套餐权益；实际扣费来源还取决于各 Key 选择的余额或套餐及套餐覆盖范围。切换本页顶部端点时，只需同步修改 config.json 的 base_url。

说明：CCSwitch 中切换 API 端点时，只修改 Endpoint/Base URL。遇到 429 时，请先检查余额、模型配额以及套餐/分组权益，不要只当作限流。
